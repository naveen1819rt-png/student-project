We will complete all 11 exercises using: - 🌐 Firefox + GitHub.com for most exercises - 🖥️ GitHub Desktop only where the exercise specifically asks for it - ❌ No Command Prompt - ❌ No PowerShell - ❌ No Git Bash - ❌ No Linux commands - ❌ No command-line Git GitHub itself says you don't need command-line knowledge to complete its basic GitHub workflow, and GitHub Desktop provides a graphical interface for common Git operations. --- PART 0 — Understand the basic words first Before touching GitHub, understand these 10 words. 1. Repository A repository, or repo, is basically your project's main folder on GitHub. Think: Repository ↓ Project folder ↓ Files + folders + history Our repository will be: student-project A GitHub repository stores the project's files and their revision history. --- 2. File A file is simply something inside the project. For our project: index.html style.css student.jpg README.md .gitignore --- 3. Commit A commit is a saved checkpoint/snapshot of your project. Imagine you're writing an assignment. You reach a good point and press: > SAVE VERSION 1 That's roughly what a commit is. Example: Commit 1 "Create portfolio page" Commit 2 "Add CSS" Commit 3 "Add Skills section" GitHub describes a commit as a snapshot of your project at a particular point in time. --- 4. Branch A branch is another version/work area of your project. Suppose your stable project is: main You want to experiment with a new feature. Instead of directly disturbing main, you create: feature So: main │ │ ┌───┴───┐ │ │ main feature │ New work Your feature changes don't automatically appear in main. That is why branches are useful. --- 5. Merge After finishing work on feature, you can bring those changes into main. That's called: Merge feature │ │ ↓ main --- 6. Pull Request A Pull Request (PR) is basically asking: > "I made changes in my branch. Can we review them and add them to main?" Example: feature │ │ Pull Request ↓ main A Pull Request lets people review and discuss changes before merging them. --- 7. Push Suppose your computer has the latest version: Computer ↓ You send your changes to GitHub. That's: Push Computer │ │ PUSH ↓ GitHub --- 8. Pull Suppose GitHub has a newer version than your computer. You download those changes: Pull GitHub │ │ PULL ↓ Computer --- 9. Fetch Fetch basically checks GitHub for newer changes. Computer │ │ "Does GitHub have anything new?" ↓ GitHub Then you can pull the changes. GitHub Desktop provides Fetch origin to check the remote branch and Pull origin to bring those commits into your local branch. --- 10. Merge conflict Imagine two people edit the same line differently. Person A:
